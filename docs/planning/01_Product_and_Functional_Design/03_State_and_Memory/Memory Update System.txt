Historical future workflow: after each interaction, a future app might decide
what should be remembered. In MVP, memory create/edit/delete occurs only through
an explicit user operation; there is no automatic candidate storage, merge,
outdated-fact update, or cleanup.
It should classify information as:
Temporary
Session-only
Project-specific
Long-term preference
Correction
Do not store

It must not save every message automatically.
Example:
{
  "memory_candidate": "User wants Canva descriptions rather than generated images",
  "category": "user_preference",
  "confidence": 0.93,
  "scope": "visual design requests",
  "storage_action": "save"
}

MVP preserves change history, allows manual correction/soft deletion, and shows
provenance. Duplicate merging and automatic outdated-fact updates are Deferred
Post-MVP.
