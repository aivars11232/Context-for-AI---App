important qualifiers
correction handling

“do not change anything else”

Local service
The context engine should run separately from the interface:
Qt/QML interface
      ↓
Local API
      ↓
Context engine
      ↓
AI models and database

This allows other applications and agents to use the same context engine later.
Recommended first version
Do not build all modules immediately.
Your minimum viable version should contain:
1. Chat interface
2. Conversation-state manager
3. Basic intent and qualifier extraction
4. Project memory
5. SQLite database
6. Context packet builder
7. Ollama connector
8. Rule-based response validator
9. Context inspection panel
10. Basic evaluation tests

The first functional pipeline would be:
User message
    ↓
Load current project state
    ↓
Extract intent, references and constraints
    ↓
Retrieve relevant memories
    ↓
Build structured context packet
    ↓
Send it to Ollama
    ↓
Validate response
    ↓
Show response
    ↓
Update session state

Later expansion

Once the basic system works, add:
Phase 2
- semantic memory retrieval
- automatic reference resolution
- correction memory
- automatic response revision

Phase 3
- multiple specialized agents
- file and code context
- cross-application context
- model routing
- confidence scoring

Phase 4
- visual context
- screen understanding
- voice context
- autonomous project tracking
- shared context across all AI agents

The central product is not merely a chatbot. It is a shared context service that every AI agent in your control center can use.
